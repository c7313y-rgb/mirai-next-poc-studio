# 学習指導要領を踏まえたカリキュラム編集

この機能は、企業の文章と文部科学省の資料を手がかりに、教員が授業を設計・確認するための候補を作ります。指導要領への自動適合判定・認定ではありません。外部AIに文章を送らず、API利用料のかからないローカルルールで動作します。

中学の資料は、高校総合探究解説に収録された中学校指導要領本文を参照しています。高校情報Ⅰは問題解決領域の導入候補に限定し、プログラミング・ネットワーク等を含む教科全内容の充足を表しません。各学校・教員による最新の原文と年間指導計画の確認が必要です。

## 企業から教員へ

1. 企業が教材名、元の文章（最大20,000文字）、参照する校種・教科、対象学年、授業時間を入力します。
2. 元の文章の全文を文・改行単位で分割します。長い文は360文字単位に分け、各記述の番号と原文位置を保持します。数値を含む情報、課題・制約、問いの候補を抽出し、後半の記述も授業活動へ反映します。
3. 「知識及び技能」「思考力・判断力・表現力等」「学びに向かう力・人間性等」の目標と、観察する成果物・行動の候補を作ります。
4. 課題の設定、情報の収集、整理・分析、まとめ・表現を、具体的な活動と残す証拠へ対応づけます。
5. 企業は候補を編集して提供します。教員は独立コピーに採用し、自校の目標と年間計画・単元での位置を記入し、活動や評価証拠を仕上げます。
6. 教員が確認チェックを行って最終承認します。承認者・日時・任意確認メモを保存します。内容を編集・保存すると確認を解除し、再承認まで新しい授業を作れません。

既に作成した授業には、その作成時点の確定教材と対応内容が保存されます。企業原本や次回用教材を編集しても、過去の授業は変わりません。

## 既存データと権限

- 起動時に `curricula.alignment` 列を追加します。既存の教材・回答・授業を削除しません。
- 指導要領の対応がない従来教材は、対象学年等から未確認の候補を補完します。従来の「承認済み」教材も、新しい授業作成前に教員の再確認が必要です。作成済み授業は保持します。
- 他社は教材を編集できません。企業は教員の最終承認を代行できません。
- 参照する公式URL・章はサーバー側の登録値を使用します。編集リクエストで偽の公式出典や確認者情報を書き込めません。
- 生徒APIは教員の確認者ID・進行メモ・企業の元文章全文を返しません。公開する活動に記した素材抜粋は生徒に表示されます。

## 限界

文章の分割・分類・抜粋はルールベースです。事実確認、文脈の完全な理解、資料の著作権・使用許諾、教科全体の網羅、指導時数や単位の認定を自動で行いません。PDF/PPTXのファイル読込は対象外です。元文章に出典や利用条件を明記し、公開前に内容を確認してください。

1コマの自己評価の変化を、学力向上や職業適性の証明として扱いません。指導要領の目標は継続的な学習で育成するものであり、学習過程・成果物・生徒の振り返りを教員が見取るために使います。

## APIと検証

- `GET /api/learning/curriculum-guidance`：公式参照候補を取得。
- `POST /api/learning/curricula/:id/guidance-preview`：所有教材の対応候補を作り直す。保存はしない。
- 生成・更新の `alignment` に校種・参照候補、自校目標、単元位置、3資質能力、4探究過程、評価証拠を保存。
- `POST /api/learning/curricula/:id/approve`：`alignmentConfirmed: true` と保存済みの自校目標・単元位置が必要。
- `tests/curriculum-guidance.test.js`：先頭700文字より後の根拠、公式出典、学校段階の差、権限、編集保存、教員承認、変更後の再確認、授業スナップショット、既存DBの移行を検証。
