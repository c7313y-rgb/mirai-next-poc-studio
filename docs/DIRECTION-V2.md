# 追加構想への対応と実装の範囲

2026-09-18時点の追加改修について、6ページの構想資料から取り入れた機能と、その限界を整理します。資料は設計の参考として扱い、初月運用を含む既存の承認済み予算と実証規模を維持しています。構想資料中の投資案を予算変更の指示とは扱っていません。資料の原文、内部の予算案、個人名は掲載していません。

今回の教材化・推薦・探究記録・参考集計は、追加の有料APIや有料データベース契約を必須とせず、既存アプリ内で動作します。開発・サーバー・保守の費用が不要になる意味ではありません。手帳OCRとコメントを実AIへ切り替える場合は、従来どおり利用料・処理先の確認と実環境での受入が必要です。

## 対応表

| 構想の意図 | 実装した機能・入口 | 実装の範囲と確認事項 |
|---|---|---|
| 企業の知見を授業に変える | 企業の「カリキュラムをつくる」。入力文全体を処理し、根拠となる原文の断片と50/100分の授業草案を表示 | ローカルの規則による草案。原文の事実確認、出典・権利・公開範囲は提供企業が確認する |
| 学校の教育課程につなぐ | 高校の総合的な探究、中学校の総合的な学習、高校の情報Ⅰの3領域に対応候補を用意。3つの資質・能力、4つの探究過程、活動と評価の証拠を編集 | 文部科学省の公開資料への参照を示す。自動の適合認定ではない。教員が自校の目標・単元の位置を記入し、対応候補を確認して承認する |
| 手帳から自分の関心に気づく | 手帳の提出・本人確認と、探究ストーリーのSTEP 1「気づく」 | 問いかけは固定文。手帳OCRとコメントのデモはmockであり、追加のAI対話エンジンは実装していない |
| 関心と社会のテーマをつなぐ | 生徒のテーマ一覧を「自分の関心に近い順」で表示し、近い理由となるタグと記録件数を示す | 本人の直近最大100件の提出記録の関心タグと、学校から配信されたテーマを照合。能力・職業適性を判定しない。別の分野や新着順も選べる |
| 越境体験を自分で計画する | STEP 2「選ぶ・計画する」で、選んだテーマ・理由・いつ・どこで・誰に・何を確かめるかを保存 | 計画と振り返りの記録機能。受入先の検索DB、予約、契約、日程調整、引率・保険の手配は行わない |
| 現場での気づきを内省へ戻す | STEP 3で、見聞きした事実・感情や前提の変化・手帳に書き戻す問いを分けて記録 | 実際に体験した内容を本人が入力する。実施の証明や学習成果の自動判定には用いない |
| 根拠を持って自己決定する | STEP 4で次の行動・取り組みたい理由・迷いを記録。各段階で提出済みの自分の手帳を最大10件まで根拠として関連づける | 自分の言葉を残すための仕組み。志望理由や出願書類の代筆はしない。根拠選択欄は直近最大200件の提出記録を表示する |
| 生徒と教員の対話を支える | 教員の「探究・面談の伴走」から担当生徒の記録を確認。共有メモ・対話予定日・対応状態を保存 | メモは生徒本人にも表示する。教員専用の相談記録ではない。企業へ個人の探究記録や面談メモは提供しない |
| 参考情報を自分で確かめる | 任意のHTTPS参考リンクと確認日を保存 | 学校・受入先・進路情報を自分で調べる補助。リンクの内容や受入、入試要件の正しさ・最新性をアプリが保証しない |
| 自発的な記述の変化を確かめる | 本人が「自分から書いた」と申告した記録について、STEP 1・2とSTEP 3・4の件数・文字数を表示。教員は期間・対象人数・前後両方に記録がある人数も確認 | 前後で問い・期間・記録回数が異なる。文字数の増加を文章力や授業の因果効果とみなさない。授業の1〜5自己評価とは別の参考集計 |
| 教員の継続希望と負荷を把握する | 教員が継続希望と指導負荷の感じ方を回答。継続希望率は回答した教員を分母として、対象人数・回答率とともに表示。負荷は「軽くなった・変わらない・重くなった」の回答人数を集計 | 継続希望の目標80%は追加構想の参考指標。元の12 KPIやK-C4の企業継続率を置き換えない。指導負荷は自己申告であり、作業時間の実測ではない |
| 実証を説明できる形にする | 教員が期間を指定して、記述量・人数・教員継続希望・指導負荷の参考集計をテキストで保存 | 生徒本文・仮名ID・学校名を含めない。少人数では推測が起き得るため、外部共有は学校の確認後に行う。自動公開・自治体への自動送信はしない |
| 学びの場面を見やすく伝える | 企業の現場、地域での体験、手帳での内省の3種類の画像と、役割別の入口・案内を整備 | 画像は架空のAI生成イメージ。実在する提携先や活動実績を示さない。生成方法とファイルは[ASSETS.md](ASSETS.md)を参照 |

## データと計測の境界

- 探究ストーリーは生徒本人と担当クラスの教員が扱います。他の生徒や企業には個人の内容を返しません。記録の更新にはバージョンを使い、別画面の更新を黙って上書きしない仕組みです。
- 探究ストーリーの本文・根拠リンク・共有面談メモは、新しい標準連携項目として外部へ送信しません。従来の授業振り返りが記録へ同期される動作とは区別します。[標準連携とKPIの定義](REQUIREMENTS.md)を参照してください。
- 記述量は担当クラスの範囲、教員継続希望率は同じ学校の有効な教員アカウントの回答を集計します。対象範囲・分母・回答率を併記し、無回答を賛成として扱いません。教員の回答は更新できるため、時系列のパネル調査ではありません。
- 標準の12 KPIを維持し、追加の参考指標と混同しません。架空デモの集計を実証結果として報告しないでください。
- 体験や進路に関する文章は機微な内容を含み得ます。共有先と保存目的を学校で確認し、実証に必要な内容を入力してください。3年間の保管や進路サービスへの提供に同意済みとみなす機能はありません。

## 今回実装していないもの

| 構想上の要素 | 現版の状態／導入時に必要なこと |
|---|---|
| JMAMの6,000社ネットワーク・実企業データベースとの接続 | 未接続。提携・利用権・掲載同意・データ形式・接続先の合意が必要。デモ企業を実在の提携先として扱わない |
| 地域や企業での実際の越境プログラム手配 | 未実装。受入先確保、学校の承認、契約、引率、安全管理、移動・宿泊・保険等は関係者が別途整える |
| 入試情報、合格者データ等のライセンス連携 | 未実装。提供元の利用権と更新責任を確認する。参考リンクの保存はライセンスされた入試データ配信ではない |
| 3年間の長期ポートフォリオ運用 | 日付付きの記録は蓄積できるが、3年保管の同意画面・学校ごとの保管期間設定・学年移行や卒業時移管・同意撤回に連動した処理は未実装。方針と運用を合意してから設計する |
| 副担任mirAI等への本番API連携 | 未接続。標準CSV/JSONの確認・出力まで。認証・項目・仮名IDの対応・再送・取込結果・国内でのデータ処理を双方で合意し、先方の環境で受入する |
| 実環境でのAI品質・学習効果の実証 | 未完了。実物手帳、学校端末、対象人数、評価期間と手順を決めて確認する。画面の実装完了は現場での受入完了を意味しない |

## 確認する順序

1. 企業が教材を作り、原文の根拠と学習指導要領の対応候補を確認して提供する。
2. 教員が採用し、自校の目標・単元の位置・活動・評価の証拠を編集、確認して最終承認する。
3. 授業を作成したら、生徒が授業前評価を保存する。教員は最初の活動を進める前に回答状況を確認する。授業終了後、生徒が授業後評価と振り返りを保存する。
4. 生徒がテーマの推薦理由を確認し、探究ストーリーで計画・体験・内省・次の行動を記録する。手帳の記録を根拠として選ぶ。
5. 教員が担当生徒の記録を確認し、生徒に共有する面談メモを保存する。本人側で共有内容を確認する。
6. 教員の継続希望・指導負荷を回答し、期間・人数・分母を確認したうえで参考集計を保存する。

コード上の主な対応箇所は `server/curriculum-guidance.js`、`server/lib/recommendations.js`、`server/journey.js`、`server/routes/journey.js` と `client/src/learning/`、`client/src/student/Themes.jsx` です。本番配備・アカウント切替は[運用手順](OPERATIONS.md)と[配備手順](DEPLOYMENT.md)を参照してください。
