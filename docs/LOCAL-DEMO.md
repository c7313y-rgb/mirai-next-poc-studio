# Macで設定済みのローカルデモを起動する

この手順は `.env`、`client/dist/`、保存済みDBがあるローカルデモ用です。`DEMO_MODE=true`、非production環境、Node.js 22.13以上が必要です。初回準備は [README](../README.md) を参照してください。

## 起動する

Finderで `scripts/start-local-demo.command` をダブルクリックします。サーバーの応答を確認してからブラウザーが開きます。表示されたURLをCodex内のブラウザーで開いても利用できます。起動時に表示される保存先を確認してください。

起動ウィンドウを閉じてもサーバーは動作します。Macの終了・再起動後は、もう一度ランチャーを実行します。スリープ中の利用や別端末からの利用を保証する仕組みではありません。24時間の公開運用には [本番配備](DEPLOYMENT.md) が必要です。

コマンドでも操作できます。

```bash
npm run local:start
npm run local:status
npm run local:stop
```

NodeがPATHにあれば、npmを介さず `node scripts/local-demo.mjs start` のように実行できます。`.command` は環境変数 `MIRAI_NODE`、PATH、一般的なインストール先、Codexの同梱Nodeを順に探します。

## 保存先と停止の扱い

- `.env` と明示した環境変数を使います。保存先は `DATA_DIR`、未指定なら `./data` です。設定やDBを自動変更・初期化しません。
- `npm run demo` は専用の `data-demo/` を使います。そのデータを本ランチャーで使うときは `.env` に `DATA_DIR=./data-demo` を指定します。
- 同じデモが起動済みなら再利用します。別サービスがポートを使用していれば起動を止めます。
- `stop` は本ランチャーが管理しているサーバーだけを停止します。別の方法で起動したサーバーは、その起動元で停止してください。
- ログと実行管理情報は `.local-demo/` に置き、公開Gitには含めません。ログは起動時に5MBを超えていた場合、1世代退避します。

## 開かない場合

| 症状 | 確認と対応 |
| --- | --- |
| URLが接続拒否になる | サーバーが停止しています。ランチャーを開き、起動完了を確認します。HTML・URLのショートカットだけでは起動しません。 |
| 起動が長時間終わらない | Finderのクラウド状態を確認します。iCloud等でファイル本体が未取得なら、プロジェクトを「今すぐダウンロード」します。実行用フォルダはローカル保持を推奨します。 |
| 依存ファイルが不足・壊れている | Node/npmを用意して `npm run setup`、続けて `npm run build` を実行します。DBの再投入は不要です。 |
| 画面のビルドがない | `npm run build` を実行します。 |
| DBが見つからない | `.env` の `DATA_DIR` を確認します。既存の記録を使う場合は新規seedで置き換えないでください。 |
| 別サービスがポートを使用している | 使用サービスを確認して終了するか、空いている `PORT` を設定します。ランチャーは他サービスを強制終了しません。 |
| 起動後に設定を変えたい | `npm run local:stop` で停止し、`.env` を編集して再起動します。 |
| その他の起動失敗 | `.local-demo/server.log` を確認します。内容を共有する場合、パス等の内部情報を確認してください。 |
