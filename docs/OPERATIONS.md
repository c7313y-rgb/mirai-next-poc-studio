# デモと実運用の切替

公開デモは架空の学校・企業・生徒を用いた操作確認用です。実際の手帳画像、氏名、学校の内部情報はデモへ登録しないでください。実運用ではデモと別のデータ保存先を作り、発行アカウントで利用を開始します。

## デモを起動する

Node.js 22.13以上が必要です。リポジトリのルートで実行します。

```bash
npm run setup
cp .env.example .env
npm run build
npm run seed:demo
npm run seed:learning
npm start
```

`.env` の `DEMO_MODE=true` で役割別の簡易ログインを表示します。`AI_PROVIDER=mock` は外部AIへ送信しません。デモ投入はデモ専用環境でのみ実施します。企業の教材作成→教員の採用と最終編集→授業開始→生徒の振り返り→共有プレビューを一通り確認してください。

## 発行アカウントへ切り替える

1. デモとは別の空の `DATA_DIR` を用意します。デモDBを実運用DBへ流用しません。
2. `.env` に `DEMO_MODE=false`、`NODE_ENV=production`、実運用の `DATA_DIR`、HTTPSの `PUBLIC_BASE_URL` を設定します。
3. 32文字以上のランダムな `PSEUDO_ID_SECRET` と、32バイトをbase64化した `DATA_ENCRYPTION_KEY` を設定します。鍵はソースコードに記載せず、安全な保管先で管理します。
4. 新しい管理者を作成し、運営画面から学校・クラス・企業・教員・生徒のアカウントを発行します。
5. デモの入口が無効であること、各アカウントが許可された範囲だけを閲覧できることを確認して利用を開始します。

```bash
npm run create-admin -- your-admin-id
```

管理者パスワードは対話形式で入力します。生徒の氏名と仮名IDの対応は学校側で管理します。仮名ID用シークレットの変更はIDの継続性に影響するため、実証期間中は維持します。

`DEMO_MODE=false` はデモデータを削除する機能ではありません。デモと実データの混在を防ぐため、空DBと新規アカウントへの切替が必要です。デモを外部公開する場合も、実運用と異なる保存先・鍵・アクセス先で分離します。

## 実AIと国内処理の確認

実証前にAIの処理先、保存先、学習利用の扱いを運営担当者が確認します。`AI_PROVIDER=bedrock` と国内リージョン向け設定が実装されていますが、設定名だけで国内処理が保証されたと判断しないでください。利用する推論プロファイル、契約・ポリシー、権限、モデル利用可否を実環境で確認し、確認結果を保管します。

直接APIの `anthropic` 設定は国内リージョン要件を満たす構成として扱っていません。既定のモデルIDは設定例であり、利用開始時に提供状況と権限を確認します。教材作成のテンプレート変換は `AI_PROVIDER` を変えても外部AI生成に切り替わりません。

実物の手帳でOCRを確認し、読み取り結果を生徒が修正して確定する流れを確認します。フィードバック、タグ、要確認表示の誤りも記録します。要確認時の担当者、連絡手段、対応時間帯は学校と決めます。

## 学校での利用準備

HTTPS、国内保存先、保存データの暗号化、日次バックアップを設定します。画像のアプリ層暗号化とは別に、DBやバックアップを置くストレージの保護も必要です。

学校端末でカメラ権限、画像提出、表示、フィルタリング許可先を確認します。1クラスの同時提出を試験し、画面応答とAI処理待ちを測定します。対象規模の想定値を実測結果として扱わないでください。

利用目的、共有範囲、保管期間と終了後の扱いを学校へ説明し、必要な同意を整えます。KPIの期間・学校開始日・対象人数・除外期間・目標を設定してから実証を開始します。

## mirAI連携の運用

現版は外部のmirAIへ自動送信しません。共有プレビューを確認し、運営画面でCSV/JSONを出力します。出力対象は必要な期間に限定し、ファイルも個人情報として管理します。

月次や実証終了時の連携を始める前に、接続先と項目名、仮名ID、関心タグ、拡張項目を合意し、テストデータの取込を実施します。出力充足率と先方取込成功を別々に記録します。画像・要確認フラグ・利用ログを連携ファイルへ追加しません。

## バックアップと終了時の処理

```bash
npm run backup
```

別の32バイト鍵 `BACKUP_ENCRYPTION_KEY` を設定してください。このコマンドはDBと参照画像をAES-256-GCMで暗号化したバックアップを作成します。日次の実行スケジュールと保管先のアクセス制御は運用環境で設定します。復元試験と鍵の保管を確認してください。

終了時は合意した期日に、対象保存先と返還済みデータを確認したうえで `npm run purge` を実行できます。削除対象を表示し、確認語の入力を求めるコマンドです。バックアップやダウンロード済みファイルは別途管理・削除し、実施記録を残します。

## 公開リポジトリの範囲

ソースコード、架空のデモを作成するスクリプト、公開用ドキュメントを管理します。`.env`、秘密鍵、DB、手帳画像、連携出力、バックアップ、元の要件書・議事録・契約資料は公開対象に含めません。

本番配備の具体的な設定は [DEPLOYMENT.md](DEPLOYMENT.md)、AI件数上限は [AI_BUDGET.md](AI_BUDGET.md) を参照してください。`npm run restore-check -- <backup>` は一時領域で復元を検証し、実データを上書きしません。
