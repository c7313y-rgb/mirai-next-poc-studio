# 実AIの呼出件数を制限する

この制限は、初月の小規模試行でAIの利用を管理するためのものです。
**円・USDの課金額を保証する上限ではありません。**

```dotenv
AI_MONTHLY_REQUEST_LIMIT=3000
AI_MAX_INPUT_CHARS=24000
```

- 実AIへの送信試行を、日本時間の月単位で全利用者・機能共通に数えます。
- 入力上限は、指示文を含むプロンプト全体です。設定範囲は1〜24,000文字、画像は最大3枚です。
- 外部送信の前にSQLiteの`settings`へ件数を予約するため、同時実行で上限を超えて予約しません。
- 通信失敗・タイムアウトでも枠を戻しません。相手側で処理済みの可能性があるためです。workerの再試行も1回ずつ数えます。
- Bedrock SDK側の自動再試行は無効です（`maxAttempts: 1`）。workerが再試行を担当します。
- 上限到達後は新しい実AI送信を止めます。入力文字数・画像数の超過で送信前に拒否した要求は数えません。
- デモの`mock`は外部送信がなく、件数枠を使いません。
- 件数はDBに残り、アプリ再起動で初期化しません。月が変わると新しい月の枠を使います。

## 初月運用で確認すること

1. AWS側にも予算通知を設定し、日次で請求実績・画像枚数・入力/出力token数を確認します。
2. 通常、画像の提出1件にOCRとコメントの2呼出を使います。3,000呼出は「3,000提出」ではありません。期間要約なども同じ枠を消費します。
3. 320生徒が月2,752件を提出すると、OCRとコメントだけで約5,504呼出になるため、初月3,000枠のまま全校規模へ拡大しないでください。まず対象クラス・提出頻度を限定します。
4. 費用や品質を確認してから翌月の枠を決めます。環境変数を変更した場合はアプリを再起動します。`AI_MONTHLY_REQUEST_LIMIT=0`で実AI送信を停止できます。
5. 上限到達でAI処理が止まった記録は、運営が状態を確認してください。件数上限を変更しただけでは、処理失敗になったジョブを自動復旧しません。

現在の月別件数は、運営がDBの`settings`にある`ai_request_count:YYYY-MM`を確認できます。
これは「送信試行の予約数」であり、AWSの課金件数やtoken使用量そのものではありません。
画像の解像度、出力token、モデル単価、為替等で金額は変わります。
DBのバックアップ復元後は件数が古い時点に戻る可能性があるため、AWS側の実績とも照合してからAIを再開します。

AWS SDKの再試行仕様: [AWS公式ドキュメント](https://docs.aws.amazon.com/sdkref/latest/guide/feature-retry-behavior.html)
