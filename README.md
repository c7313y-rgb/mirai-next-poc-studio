# 副担任mirAI NEXT — PoC Studio

企業の知見を学校の探究授業へ変え、生徒の振り返りをキャリアデザインにつなぐWebアプリです。企業・教員・生徒の専用画面、運営用KPI、デモログインを備えています。

![企業と学校をつなぐ学びのイメージ](client/public/images/enterprise-v2.webp)

> **このバージョンはPoCです。** デモは架空データ、手帳OCR・コメントはmockです。教材変換とテーマ推薦はローカルのルールで処理します。学習指導要領との対応は候補を示し、教員が自校の計画に照らして確認します。副担任mirAIの共有データを確認・出力できますが、mirAI本体への外部送信・取込確認は未接続です。画像はAI生成です。

## すぐに体験する

Node.js 22.13以上とnpmを用意し、リポジトリのルートで実行します。

```bash
npm run setup
npm run demo
```

[http://localhost:3000](http://localhost:3000) を開き、「企業の方」「教員の方」「生徒の方」を選んでデモ体験ボタンを押してください。画面下から運営のKPIも体験できます。初回はビルドとデモデータを自動作成し、次回以降は保存済みデータを維持します。デモ専用保存先は `data-demo/` です。既存DBを上書きしません。

### 5分で確認する流れ

1. **企業**：カリキュラムをつくる → コンテンツと対象の学習領域を入力 → 原文の根拠・授業案・指導要領の対応候補を確認、編集 → 学校へ提供。
2. ログアウトして**教員**へ：教材ライブラリ → 教材を採用 → 自校向けに編集。自校の目標・年間計画での単元の位置を記入し、対応候補を確認して確認欄にチェック → 保存 → 最終承認 → クラスに授業を作成。
3. ログアウトして、そのクラスの**生徒**へ：授業に参加する → **授業前の理解度を保存**。予定中または最初の活動中に保存します。次の活動へ進むと事前回答は締め切られます。
4. ログアウトして**教員**へ：授業の進行 → 開始 → 各活動を進める → 終了。教材は授業作成時にスナップショット化されます。
5. 再び**生徒**へ：同じ授業を開く → 授業後の理解度・学び・次の行動・関心分野を保存 → わたしの未来で学びの変化とmirAI共有予定データを確認。企業画面では個人を示さない集計で反応を確認できます。

進行中・予定・完了のサンプル授業があるため、途中からの体験も可能です。1台で役割を切り替える場合はログアウトしてください。同じブラウザ内のタブはログインセッションを共有します。

### 設定済みのMacで、次回から開く

`.env`・ビルド・保存済みDBがあるローカルデモでは、Finderから `scripts/start-local-demo.command` をダブルクリックしてください。サーバーの起動を確認してからブラウザーを開きます。ターミナルを閉じてもサーバーは動作します。Macを再起動した場合はもう一度このファイルを開いてください。URLやHTMLのリンクだけではサーバーは起動しません。

`npm run local:start`、`npm run local:status`、`npm run local:stop` でも操作できます。既存の `.env` とDBを使い、データを初期化しません。`npm run demo` の `data-demo/` を使う場合は、その保存先を `.env` の `DATA_DIR` に指定してください。設定・エラー時の確認方法は [ローカル起動の手順](docs/LOCAL-DEMO.md) を参照してください。

## 実装した機能

| 画面 | 主な機能 |
| --- | --- |
| 企業 | 自社コンテンツの教材化、50/100分の授業案、原文の根拠と学習指導要領の対応候補、目標・活動・評価観点の編集、学校への提供、自社教材の採用・理解度集計、素材提出 |
| 教員 | 提供教材の採用、原本と独立した最終編集・承認、クラスへの配信、授業進行、回答状況・自己評価の前後比較、生徒記録・コメント・要確認管理、探究ストーリーの確認と生徒と共有する面談メモ、実証の参考集計 |
| 生徒 | 配信授業への参加、振り返り提出・更新、手帳撮影と本人確認、理由を確認できる関心順のテーマ推薦、体験計画から自己決定までの4段階の探究記録、関心タグ・次の行動・学習履歴、mirAI共有データの可視化 |
| 運営 | 12 KPI、期間・学校別の分析、アカウント一括発行・QR、テーマ・アンケート、CSV/JSON連携出力、操作ログ |

授業の振り返りは既存の記録に同期され、KPIと標準連携出力にも反映されます。理解度は1〜5の自己評価であり、成績・職業適性・授業の因果効果を示す数値ではありません。KPIの目標は案です。

「探究ストーリー」では、気づき・体験計画・現場で見た事実と心の動き・次の自己決定を自分の言葉で残せます。提出済みの手帳を根拠として結びつけ、先生との対話へつなげます。問いかけは固定文で、志望理由を代筆しません。学校・企業との実際の体験手配や入試情報サービスは含みません。企業の現場・地域での体験・手帳の内省を示す3種類の画像は、架空の場面として表示しています。

## デモと発行アカウント

`DEMO_MODE=true` のときだけ簡易ログインを利用できます。`false` にすると簡易ログイン、デモID/PW、デモQR、既存のデモセッションを無効にします。運用時は空の別DBを作り、運営画面から発行したアカウントで利用します。

| デモの役割 | ID | パスワード |
| --- | --- | --- |
| 企業 | `c-01` | `demo1234` |
| 教員 | `t-a` | `demo1234` |
| 生徒 | `s-aa-01` | `demo1234` |
| 運営 | `admin` | `demo1234` |

実証用のデータを公開デモに入力しないでください。詳細は [運用と切替](docs/OPERATIONS.md) を参照してください。

## 開発・検証

```bash
npm test
npm run build
# 個別に設定して起動する場合
cp .env.example .env
npm run seed:demo
npm run seed:learning
npm start
```

テストは認証・権限分離、教材提供から授業・振り返りまで、独立編集と授業スナップショット、少人数集計の抑制、デモ無効化、KPIの期間/学校範囲、連携データ、CSV安全性を確認します。GitHub Actionsでもテストとビルドを実行します。

- サーバー：Node.js / Express / SQLite（外部DB不要）
- UI：React / Vite / ハッシュルーティング
- 保存：サーバーのSQLiteと画像ストア。リロード・再起動後も保持
- AI：既定mock。本番の実AIは国内処理を確認したBedrock設定を使用し、直接Anthropic設定は本番起動時に拒否します。教材化とテーマ推薦はローカルのルールで処理し、外部AIを呼び出しません
- 配置：Dockerfile付属。認証API・DBが必要なためGitHub Pagesへの静的配置だけでは動作しません

## データの境界

- 生徒は本人、教員は担当クラス、企業は自社教材の範囲をサーバーで検証します。
- 企業の学習効果は5人以上の集計のみ。個人の振り返り・仮名ID・キャリアデータを返しません。
- 学校別値、関心タグ、匿名の声は少人数抑制を適用し、匿名の声は運営承認後に表示します。
- 標準mirAI連携には撮影画像・要確認フラグ・利用ログを含めません。
- キャリア画面の拡張JSONは共有項目を提案するプレビューです。先方での取込成功を意味しません。
- 探究ストーリーと面談メモは本人・担当教員の範囲で共有し、標準mirAI連携へ追加しません。面談メモは生徒にも表示されるため、教員専用の記録を入力しないでください。
- `.env`、DB、画像アップロード、バックアップ、添付原本は公開対象に含めません。
